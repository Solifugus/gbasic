# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

gBASIC is an experimental BASIC-family language implemented as a tree-walking
interpreter in C11. The single binary `gbasic` lexes, parses, and evaluates
`.bas`/`.gb` source files (both extensions are used interchangeably). Version is
`0.1.0-rc8`. See `README.md` for the language feature surface and `docs/` for
design/reference documents.

## Build & run

```sh
make                       # build ./gbasic (runs bison, then cc)
make clean && make         # full rebuild
./gbasic program.bas       # run a program
./gbasic --tokens program.bas   # dump lexer tokens
./gbasic --ast program.bas      # dump parsed AST
./gbasic --add-loads program.bas # print source with suggested `load` lines
./gbasic --json-diagnostics program.bas # emit parse/runtime diagnostics as JSON on stderr
./gbasic --line-buffered program.bas # flush stdout per completed line (pipes block-buffer by default)
./gbasic --version
sudo make install          # install to /usr/local (binary + stdlib); PREFIX overridable
```

Build requires a C11 compiler, `make`, and `bison`. Optional native modules are
detected at build time via `pkg-config` and gated behind `HAVE_*` macros in the
`Makefile` (`HAVE_GTK`, `HAVE_LIBPQ`, `HAVE_SQLITE3`, `HAVE_ODBC`, `HAVE_LIBCURL`,
`HAVE_LIBXCRYPT`, `HAVE_LIBCRYPTO`, `HAVE_LIBXML2`, `HAVE_GIR`). The interpreter always builds; a missing dependency turns the
affected feature into a clean runtime error rather than a build failure. When
adding code that touches an optional library, guard it with the matching
`#if HAVE_*` block (the existing module code in `src/eval.c` is the pattern).

`GBASIC_PATH=stdlib` tells the interpreter where to resolve `load`ed standard
libraries (`stdlib/*.bas`); set it when running from the source tree, e.g.
`GBASIC_PATH=stdlib ./gbasic examples/gui/demo.bas`. After `make install` this is
unnecessary: the install path (`$(PREFIX)/share/gbasic/stdlib`, default
`/usr/local/share/gbasic/stdlib`) is compiled in as `GBASIC_DEFAULT_STDLIB` and
searched as a fallback when `GBASIC_PATH` is unset or doesn't resolve a library.
`GBASIC_PATH` still wins when set, so it remains the dev override.

## Architecture

The pipeline is the classic lex → parse → AST → walk, but note where the weight
sits:

- `src/lexer.c` (`include/lexer.h`) — hand-written lexer. Has stateful modes
  (`modifier_content_mode`, `lens_content_mode`, `consider_depth`) because
  modifier `(...)=` clauses and `consider` blocks need context-sensitive
  tokenization. Token list lives in `lexer.h`.
- `src/parser.y` — Bison grammar (`-d` generates `parser.tab.c`/`.h`). Builds the
  AST. Regenerated automatically by `make` when `parser.y` changes.
- `src/ast.c` (`include/ast.h`) — AST node definitions and constructors.
  `AstStmtKind`/`AstExprKind` enumerate every node type.
- `src/eval.c` — **the entire runtime, ~18k lines.** This is the file you will
  most often edit. It contains the `Value` model, environment/scope handling,
  watchers, locks, error handling, the date/time/money/file value types, AND the
  full implementation of every optional module — `sqlite`, `pg` (PostgreSQL),
  `odbc` (any ODBC-reachable database),
  `webclient`, `webserver`, `xml` (libxml2), the GTK 3 `gui`, the `gi`
  GObject-Introspection bridge (GTK 4), and the libcrypto crypto builtins — each
  inside `#if HAVE_*` guards. Module dispatch (`sqlite.query`, `pg.exec`,
  `gi.new`, etc.) is resolved here, not in separate files.
- `src/builtins.c` (`include/builtins.h`) — **only a name registry.** A flat list
  of builtin function names so the parser/evaluator can recognize them. The
  actual implementations live in `src/eval.c`. To add a builtin: register the
  name here, implement the behavior in `eval.c`.
- `src/main.c` — CLI entry point and flag handling.

## Tests

Tests are golden-file based: a source file plus a sibling `.out` holding the
expected stdout. Output is compared verbatim (string equality), so update the
`.out` when intended output changes. Negative tests pair a `.bas` with a `.err`.

```sh
./tests/run_all.sh          # EVERY suite, discovered by GLOB. Use this as the gate; the per-suite lines below are for running one thing while working on it. Reports a suite that SKIPPED ENTIRELY separately from one that passed -- a green line that ran no assertions is the other way a gate shrinks -- and NAMES the manual tier it excludes rather than dropping it quietly. Takes a substring filter (`tests/run_all.sh web`); SUITE_TIMEOUT and RUN_MANUAL override
./tests/run_examples.sh     # baseline positive suite (runs `make clean && make` first)
./tests/run_negative.sh     # error/diagnostic suite
./tests/run_core.sh        # WP-CORE-1: the checks a golden CANNOT express. `sleep(0.30)` is asserted against the WALL CLOCK (nanosleep guarantees the full interval, so any shortfall is real) and `env` against a variable this script sets and unsets -- both are facts about the world, and a golden can only record what the binary said about it. The third tier is the read-then-shadow warning, and it is the interesting one: gBASIC has NO CLOSURES, so a function that READS an enclosing variable and then assigns the same name gets a silent function-local instead of writing back, which is almost never what was meant. The fixture's own stdout is the proof of that semantics (bump() runs twice, both calls see 6, the global stays 5), and the warning is required to (a) appear on stderr EXACTLY ONCE -- deduplicated across calls, not once per call, or a loop would bury the program in its own advice -- (b) carry file:line:col, and (c) change NOTHING: same stdout, same exit 0. SELF-CHECKING AND FORCED: every defect produces a RANKED LIST OF PLAUSIBLE EXPLANATIONS (names, numbers, an order) and a golden would record whichever story came top as expected. NO PROBABILITY IS CLAIMED: the charter's §11 showed "confidence .91" for a cause and nothing in the data supports that, so what is computed is SET AGREEMENT (hits/union) reported WITH ITS DEFINITION ATTACHED, and a tier asserts the definition travels with it. PARSIMONY IS NOT IMPOSED, it falls out -- a hypothesis predicting 15 cells and explaining 1 has over-predicted 14 -- proven by the perturbation that scores on HITS ALONE, which makes "everything" the winning explanation. A `discriminator` is REQUIRED (a hypothesis nobody can imagine a test for is a story, and a story scores against a pattern just as well); `predicts` is DECLARATIVE rather than a function value, because a prediction that cannot be written into provenance cannot be audited. NOTE a real gBASIC trap caught here: `find` returns `nothing` on a miss and `is_unknown(nothing)` is FALSE, so an is_unknown guard reads as "found at index nothing" -- use `contains`. Headless, GI-independent, never skips (bar valgrind)
./tests/run_decision.sh   # decision.evaluate -- the SECOND increment of Business Automation Reasoning, from Recipe 5 (docs/automation_recipe_05_what_to_do.md), the first recipe to cross this boundary at all: recipes 1-4 all stop at the finding, leaving two thirds of the architecture unexamined. SELF-CHECKING AND FORCED, more sharply than run_insight: every defect here produces a DEFENSIBLE-LOOKING RECOMMENDATION -- an option, an expected value, a rationale -- and a golden would record "restock and promote" as expected and defend it whether or not the number underneath had ever been established. THE LOAD-BEARING TIER IS R9, the refusal the recipe PRODUCED rather than one reasoned to: the same intervention over the same data gives EV +7,497 sized off the aggregate decline and -4,899 sized off the cell that actually cleared -- ACT against DO NOT ACT -- and the Finding had ALREADY said the aggregate was not established. Found by printing values, not by the suite. Fixed twice over: the library now RAISES if the sweep disagrees with the point estimate at the nominal assumption (scale 1 computes what the point estimate computed, so they must agree), and the fixture asserts assurance as a DIFFERENCE between a robust recommendation and a marginal one (0.95 against 0.43). Four perturbations proven red including that one. Headless, GI-independent, never skips (bar valgrind)
./tests/run_automation.sh # automation.execute/would/rehearsal/observe -- the THIRD increment of Business Automation Reasoning (Recipe 6), which CLOSES THE ARCHITECTURE: until something could act, R5 (simulation as a precondition) and the ENFORCEMENT half of R6 had never been tested at all. THIS IS THE LAYER WHERE A DEFECT IS NOT A WRONG NUMBER -- it is something HAPPENING that should not have -- so the refusal tiers assert an ABSENCE and prove it with a SIDE EFFECT ON DISK (the executor writes a marker file; "nothing happened" means the file is not there), since a return value proves nothing about whether the executor ran. THE LOAD-BEARING TIER IS THE SHARED GATE: `would` and `execute` both call one `_gate` and neither holds a copy of the rules, because R5's entire argument is that a rehearsal tells you what the LIVE run will do -- if they could disagree the rehearsal would describe a DIFFERENT PROGRAM. Asserted over a six-case matrix with a CONTROL that the matrix lands both ways, since unanimous agreement over all-refusals proves nothing. R5 IS CHECKED BEFORE AUTHORITY, deliberately, with its own tier: approval does NOT substitute for a rehearsal, because a human asked to approve an unrehearsed process has nothing to approve ON. `would` cannot act BY CONSTRUCTION (it takes no executor at all, rather than an executor plus a dry_run flag). THE RECIPE ITSELF IS ASSERTED because its demonstration is the argument for the layer: the same process at two granularities replayed over a year, where the COARSE one MISSES the collapse it exists to find and every alarm it raises is FALSE, while the fine one catches it and raises nothing else -- same code, same data, and nothing in the source says which you have. THE RECIPE ALSO FOUND A DEFECT IN `insight` THAT insight's OWN SUITE COULD NOT: a cell was standardised against a spread INCLUDING ITSELF, so max|z| = (n-1)/sqrt(n) -- at 8 cells that ceiling is 2.47, BELOW the threshold, meaning the test could never fire however completely a cell had collapsed and would report "within ordinary variation" for a cell that had gone to zero. Fixed with leave-one-out standardisation and a t threshold (n-2 df, since a LOO residual is not normal) plus a refusal below 4 cells. Five perturbations proven red. ~10s. Headless, GI-independent, never skips (bar valgrind) RECIPE 7 IS ASSERTED HERE TOO and is the sharpest measurement in the lab: an intervention whose true effect is EXACTLY ZERO (nothing in the fixture alters a number after the decision) shows a ~49% apparent "recovery" -- the number a learning loop would have stored, and the number recipe 5 had GUESSED at 60% and flagged as what its recommendation was most sensitive to. It is entirely REGRESSION TO THE MEAN: an action is taken precisely BECAUSE a measure is extreme, and extremes contain noise that does not repeat. The cells nobody touched recovered just as well (85.5%), and BOTH halves are asserted since the apparent recovery alone is only half the argument. That produced R10 (an uncontrolled outcome is not evidence of an EFFECT) and `automation.assign` -- the concept of deliberately NOT acting, which the architecture had no way to express, DETERMINISTIC in the key because a replay must make the same assignments as the live run (R5). ./tests/run_credit.sh      # stdlib/credit.bas -- credit analytics over a PORTFOLIO (docs/credit_analytics_design.md), Phase 3's second increment and the item lending_design §8 deferred until fake.plant existed. `lending` answers questions about ONE loan; this answers questions about a BOOK -- vintage curves, roll rates, migration, charge-off -- none of which is derivable from a single loan or is arithmetic about balances: they are questions about STATES OVER TIME. THE INPUT IS A STATUS TABLE, NOT A LIST OF LOANS, and everything follows from that: `apply` is a fold, so a 5,000-loan book over 36 month-ends is 180,000 folds, and real portfolio data arrives as a monthly performance record per loan (the shape published loan-level datasets and any servicer extract take) -- a library that could only read our own loans could not be pointed at a real book. `credit.observe` is the BRIDGE, so our machinery is a producer rather than a special case. DELINQUENCY IS DECLARED AND THE INDUSTRY DISAGREES: mba counts PAYMENTS MISSED (30 days delinquent the day after one is missed), ots counts DAYS PAST DUE, and on a monthly loan they run a month apart for the whole life of a delinquency -- asserted as a DIFFERENCE (mba harsher on every row where they differ), never as a value. ATTRITION IS A STATE, NOT A HOLE: paid_off and charged_off are buckets nothing rolls out of, and a loan present at t and missing at t+1 is reported `unobserved` rather than dropped -- dropping it makes a book look like it is CURING, an ordinary-looking percentage with nothing raised. That gives the load-bearing invariant, the counterpart of the accounting equation: EVERY LOAN OBSERVED AT t IS ACCOUNTED FOR AT t+1, row totals plus unobserved equalling the starting bucket. Never enforced anywhere -- it falls out of correct bucketing, which is what makes it a good test. AND THE TIER THAT KEEPS IT FROM BEING VACUOUS is the one where four accounts GO SILENT: `observe` emits a row for every date once a loan is written, so nothing ever disappears from a table it produced and a library that never counted attrition would reconcile perfectly (measured: with the unobserved count removed, the main book reports ZERO mismatches and only the silent tier goes red). The rate form needs its OWN check for the same reason, since reconciliation runs on counts. VINTAGE IS MONTHS ON BOOK, NEVER CALENDAR MONTH -- indexed by calendar every cohort's curve starts at a different age and the result is a smooth meaningless line that does not look like a mistake; a cohort's curve STOPS at the age it has reached, so an unlived age is absent rather than 0% ("no losses" where the truth is "no data"). basis original/outstanding is REQUIRED, and the outstanding denominator counts a delinquent loan ONCE (`is_bad or still_alive`, not the sum). A charge-off is READ from the record, never inferred from days past due, and gross/recoveries are reported separately. THE PLANTED-PORTFOLIO TIER is what §8 asked for: four of twenty accounts in the middle cohort stop paying, chosen by `fake.sample` with NO marker in the data, and vintage must report exactly 4/20 for that cohort and 0 for its neighbours. Self-checking not golden, forced: every defect here produces an ordinary-looking PERCENTAGE. Eight perturbations proven red, each caught by the tier written for it. Fixture is ~12s. Headless, GI-independent, never skips (bar valgrind)

Tiers: SEMANTICS (self-checking, because a default that silently fails to apply yields `nothing`, which prints as an ordinary word and which a golden would enshrine); REFUSALS (9 -- a gap before a required parameter, four non-literal default forms, and the three constructs that share `parameter_list` but cannot honour a default, since a modifier's parameters come from the invoking clause, a program block's from argv and a server handler's from the URL pattern; each asserts a nonzero exit, the message, AND that NOTHING RAN); ACTOR (the child is a fork+exec that never saw the call site -- the parent sends only the supplied arguments and the child fills the tail, rather than materializing defaults onto the wire where a child built from different source could disagree); GRAMMAR (bison must still report ZERO conflicts -- not decoration, since the project rejected `IDENT expression` as a statement form over 4 MEASURED conflicts, and `IDENT OP_EQ` inside a list of bare identifiers is exactly the shape that could collide with assignment); VALGRIND. THE LEAK IS THE LESSON: the new per-parameter-list `defaults` array must be freed in SIX places (function, modifier, program, watch, server item, modifier signature) and missing three of them turned 22 SUITES RED on their own valgrind tiers -- a few bytes per parse, invisible to every functional test. Two of the six were only found by valgrind naming the exact grammar line. Headless, GI-independent, never skips (bar valgrind)
./tests/run_continuation.sh # PLAT-CONT: a line break inside an unclosed `(`, `[` or `{` continues the statement. gBASIC had NO line continuation in any form, so every long expression was assembled -- `join([...], " ")` is the shape that showed up in the wild, once per `create table`. The mechanism needs no new syntax and no trailing marker to forget, because the brackets the author already wrote say where the statement ends; it is a LEXER change only and the grammar is UNTOUCHED (zero conflicts before and after). The load-bearing pair is EQUIVALENCE and TERMINATOR. EQUIVALENCE states transparency as a FACT rather than a claim: the same program written on one line and across many must produce a BYTE-IDENTICAL TOKEN STREAM with positions stripped, and identical stdout -- structural, so it cannot drift the way a golden of the multi-line form would, with a coverage floor since two EMPTY streams are also identical. TERMINATOR is THE CONTROL, and every other tier is satisfied without it by a lexer that suppressed newlines UNCONDITIONALLY: outside brackets a newline still terminates, the depth returns to zero when a bracket closes, and a bracket inside a STRING or a COMMENT is not depth at all -- the two places a character-counting implementation goes wrong and swallows the rest of the file. Other tiers: FORMS (every bracket kind in every position the grammar admits one, incl. blank lines and per-line trailing comments inside an argument list), MODES (the two STATEFUL lexer modes -- brace-modifier content, and `consider`, which recognises its branches by COLUMN -- since nothing in the continuation tiers writes either and neither would be noticed breaking), REFUSAL (an unclosed bracket at EOF NAMES the opener and its line, because the parser's own report blames "unexpected end of file" and that is the WRONG END of the file -- the mistake is where the bracket opened; one that runs into a following statement is reported there instead, which is the more common typo and already reads well), DEPTH (200 levels each on its own line, past the fixed-size 64-entry opener stack, under valgrind -- the stack is fixed by design since nesting that deep is pathological, so what matters is that going past it does not write out of bounds). Red-proofed: FORMS, EQUIVALENCE, MODES and REFUSAL all fail against the pre-change binary; TERMINATOR correctly PASSES there, being the control, and was proven red separately against a copy whose depth never decrements. Headless, GI-independent, never skips (bar valgrind)
./tests/run_smtp.sh # PLAT-MAIL: composing and sending email (docs/mail_design.md). gBASIC could not send mail AT ALL, so a program needing a notification shelled out to `sendmail` -- a hard dependency on a local MTA, no way to reach an authenticated relay, and no error the program could read. THE SPLIT IS WHAT MAKES THE SUITE THOROUGH: composition is `stdlib/mail.bas`, pure gBASIC, so the whole of it is checkable WITH NO NETWORK (the run_web_routes lesson); the native `smtp` module owns only the wire. Each layer refuses at the boundary it can SEE -- headers there, SMTP commands here -- because a rule enforced in the wrong layer can be walked around. Tiers: COMPOSE (SELF-CHECKING not golden, 23 assertions each stating its own expected answer, because every defect here -- a body sent 7bit that needed base64, a Bcc reaching the headers, a boundary occurring inside a part -- produces a message that STILL LOOKS LIKE A MESSAGE and a golden would record it as expected); GOLDEN (byte-exact, with only the Message-ID and boundaries masked, Date pinned by the fixture and TZ=UTC by the runner); ORACLE, THE STRONGEST TIER (every composed message parsed by python3's `email` module, an INDEPENDENT implementation, asserted on what a mail CLIENT sees -- encoded-words decoding back to the author's text, a Date parsing to the right instant, attachment bytes surviving base64; validating with anything of ours would only prove we agree with ourselves, and the Date formatter is separately byte-identical to python's email.utils across all seven weekdays); REFUSAL (14 compose refusals, each beside its NEAREST LEGAL NEIGHBOUR, since a refusal suite with no control is satisfied by refusing everything); SEND-REFUSAL (15 envelope/configuration refusals needing no relay, plus a control that must get PAST validation and fail at the SOCKET); WIRE (through a sink recording exact bytes -- three things no functional test can see from outside: CRLF framing, DOT-STUFFING, and Bcc in RCPT TO but not in DATA); AUTH; REJECT; TLS; VALGRIND. THREE DEFECTS THE SUITE FOUND, none of which would have raised anything. (1) LIBCURL ALREADY DOT-STUFFS -- stuffing in smtp.c as well put THREE dots on the wire where the body had one, which the receiver un-stuffs to two: a corrupted message that is delivered, accepted and plausible. Found by reading the wire capture, not the docs. The tier therefore asserts the OUTCOME (the delivered body is byte-identical to what the program wrote) rather than who did the stuffing, and the fixture body is ASCII ON PURPOSE, since a non-ASCII body goes base64 and has NO line starting with a dot -- a UTF-8 fixture cannot exercise dot-stuffing at all and would pass on a build that never stuffed anything. (2) THE TRAILING NEWLINE is transport framing for 7bit and CONTENT for base64, so the same body decoded WITH a trailing newline in one encoding and WITHOUT it in the other -- a difference decided by a rule the author never sees. (3) `weekday` is ISO 1-7 (Mon..Sun), and a Sunday-first day table read with it is right FOR SATURDAY ALONE -- which is the day the first hand-check happened to fall on. Also added `zone_offset(dt)`, the one-argument form: a datetime carries no zone, so without it a program can read the wall clock and cannot say what it is offset from, making an RFC 5322 Date unwritable. Skips without python3 (the sink and the oracle) or without libcurl in the build; the TLS tiers skip without openssl. All loopback; nothing leaves the machine
./tests/run_parse_exit.sh   # a REPORTED parse error must fail the parse (DOGFOOD item 6). `yylex` signals a token the grammar cannot map by returning 0 -- end of file -- and bison cannot tell that from a real one. Inside a block the synthetic EOF lands where the grammar refuses it, which is the ONLY reason this looked like the exit-code inconsistency it was filed as; at TOP LEVEL the grammar accepts, so the file parsed as whatever preceded the bad token: the statements before it RAN, everything after it disappeared, and the exit was 0. Not `dim`-specific (any unlexable byte did it) and not cosmetic (the bare stderr line bypassed the diagnostics sink, so --json-diagnostics emitted a non-JSON line INTO a JSON stream -- Studio's own consumer). Four claims: LOCATED (every stderr line matches the located form, which is how a sink-bypassing line is caught generically rather than by naming the one we knew about), NONZERO, NOTHING_RAN (stdout empty -- the truncation is what made this dangerous, not the exit code), ONE_CAUSE (no follow-on blaming "unexpected end of file", which is a fiction the synthetic EOF invented). ./tests/run_process_lifetime.sh # "nothing this interpreter started outlives it" -- docs/reference.md says it in bold, and it was enforced by a teardown pass at the end of eval_program, which a SIGKILL never reaches (DOGFOOD item 4: four gBASIC children found sleeping two days after the runs that started them, three with their working directory already deleted). A promise about surviving a kill can only be kept by the KERNEL, so all three fork sites now arm PR_SET_PDEATHSIG between fork and exec, as the actor path has since it was written. Written from the observable side because there is no other honest way: start a child, kill -9 the parent, look for the child. Tiers: START, ABANDONED (the handle dropped, which is deliberately NOT lethal, so the child is running with nothing holding it -- the exact state the userspace sweep exists for and cannot reach under SIGKILL), RUN (killed mid-synchronous-child), CLEAN_EXIT (the control -- a normal exit still reaps and the program still works), EVERY_FORK_ARMS (counted against the fork sites, not grepped for the symbol: the failure this guards is a NEW fork site that forgets, which "is PR_SET_PDEATHSIG mentioned somewhere" cannot see). Each child carries a per-run marker in its argv so pgrep cannot match a stray from a concurrent suite, and the suite waits for the child to EXIST before killing anything -- a child that never started is trivially "gone" and would pass vacuously. NOTE the design doc had said process-lifecycle behaviour "does not fit a stdout golden test" and left it hand-verified, which is how the other two fork sites went unnoticed for two months: that was a statement about goldens, not about testability. Headless, never skips

## Conventions

- Optional-dependency code must stay behind its `#if HAVE_*` guard and degrade to
  a runtime error when the feature is compiled out.
- Design docs in `docs/` may describe unimplemented future work; check the
  implementation-status documents (and `eval.c`) before treating a proposal as a
  shipped feature. `docs/historical_development_archive.md` records completed
  phases.
- The `use`/`--add-uses` syntax is legacy and retained only for compatibility;
  prefer `load`/`--add-loads`.

## House rules

Identical to `AGENTS.md` — the two entry files carry the same rules:

- **Before writing gBASIC code**, read `docs/ai/START-HERE.md` and follow it
  (`UNLEARN.md` first). gBASIC diverges from QBasic/VB intuition in ways that fail
  silently.
- **When you work around a gBASIC limitation or surprise**, append an entry to
  `/DOGFOOD.md` using its template *before continuing*.
- **Evidence standards:** tests-first where feasible; keep goldens byte-exact (a
  behavioral change that moves a golden is a deliberate, listed rebaseline);
  measure, don't assume; report what you could not verify. Never mark anything
  "verified".

## gBASIC Studio

Studio lives in its own project: `~/development/gbasic-studio`. It is not built
here and its libraries are not in this `stdlib`. What DID stay is everything that
was general rather than Studio-specific — `persist` (crash-safe versioned
persistence) and `filetree` (a directory as a value tree), both extracted from
Studio and documented in the cookbook. Studio consumes this repo's platform
surface (`source_outline`, `try_decode`, `process.*`, `--line-buffered`,
`print to error`, `atomic_replace`, the `gi`/`gtk`/`sourceeditor` libraries) and
finds it via `GBASIC_PATH`; nothing here depends on Studio.
